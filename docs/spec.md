## 1. 문제

부모가 처음 심부름을 보내는 어린아이에게는 목적지 이동, 방향 전환, 주변 위험 인지, 물건 확인, 귀가까지 연속된 도움이 필요하다. 기존 지도 앱은 화면 읽기와 추상적 경로 이해를 전제로 하므로 아이가 직접 따라가기 어렵고, 부모도 진행 상태를 안심하고 확인하기 어렵다.

## 2. 목표

- 3시간 개발 종료 시 부모가 심부름을 만들고 아이가 참여 코드로 접속할 수 있다.
- 아이가 마트까지 가는 길과 집으로 돌아오는 길에서 음성용 안내 문구를 받을 수 있다.
- 부모가 2~3초 polling으로 아이 위치, 상태, 알림을 확인할 수 있다.
- 아이가 보낸 샘플 카메라 프레임으로 도로 상황 경고와 상품 확인 결과를 받을 수 있다.

## 3. 비목표

- WebSocket, push 알림, 백그라운드 알림
- 다중 서버 확장, 고가용성, 운영 관측 인프라
- 높은 인식률을 위한 모델 튜닝과 정식 평가 체계
- 도로 횡단 안전에 대한 확정 판단 (`건너도 된다` 금지)
- 장기 보존용 미디어 저장소와 운영용 개인정보 체계

## 4. 대상 사용자와 핵심 시나리오

| 사용자 | 상황 | 기대 결과 |
| --- | --- | --- |
| 부모 | 심부름 목적지와 물건을 지정하고 아이 진행 상황을 확인하고 싶다 | 참여 코드 생성, 현재 위치·상태·알림 확인 |
| 아이 | 화면을 오래 보지 않고 심부름을 끝내고 싶다 | 음성 중심 길안내, 위험 주의, 물건 확인, 귀가 안내 |

## 5. 기능 요구사항

- [ ] P0: 심부름 생성, 참여 코드 조회·참여
- [ ] P0: `WAITING → GOING → SHOPPING → RETURNING → COMPLETED` 상태 흐름
- [ ] P0: 아이 위치 업데이트와 다음 안내 문구 계산
- [ ] P0: 경로 이탈·역방향 판단과 부모 알림 이벤트 저장
- [ ] P0: 도로 상황 비전 판단 결과를 `STOP | CAUTION | UNKNOWN`으로 정규화
- [ ] P0: 상품 확인 결과를 `MATCH | SIMILAR | MISMATCH | UNKNOWN`으로 저장
- [ ] P0: 부모 화면용 상태·위치·이벤트 polling 조회
- [ ] P1: 수동 상태 보정과 재시도 보조 명령

## 6. 비기능 요구사항

- 보안: 비밀값은 저장소에 커밋하지 않는다.
- 관측성: 핵심 실패는 원인을 확인할 수 있는 로그를 남긴다.
- 사용성: 핵심 시나리오는 시연 환경에서 중단 없이 완료되어야 한다.

## 7. API 및 데이터 계약

핵심 엔터티:

- `Mission`: 심부름 본체, 목적지/귀가 좌표, 상태, 참여 코드, 역할 토큰
- `MissionItem`: 구매 대상 물건
- `LocationPoint`: 아이 위치 샘플
- `MissionEvent`: 부모 화면 알림 이벤트
- `ItemCheck`: 상품 확인 결과

핵심 API:

- `POST /missions`
- `POST /missions/join`
- `POST /missions/{missionId}/locations`
- `POST /missions/{missionId}/road-checks`
- `POST /missions/{missionId}/items/{itemId}/checks`
- `POST /missions/{missionId}/commands`
- `GET /missions/{missionId}/snapshot`

## 8. 완료 조건

- [ ] P0 사용자 시나리오가 처음부터 끝까지 동작한다.
- [ ] 핵심 경로에 자동화 테스트 또는 재현 가능한 수동 검증 절차가 있다.
- [ ] 실행 방법과 필요한 환경 변수가 각 앱 README에 기록되어 있다.
- [ ] 미완료 범위와 알려진 제약이 문서화되어 있다.
- [ ] 아이 안내 응답에서 `건너도 된다`와 동등한 확정 표현이 나오지 않는다.
